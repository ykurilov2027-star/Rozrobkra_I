# ПР10. Надійний AI-сервіс і AI UX

Матеріали до десятої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР10.pdf`, виданому до заняття.

## Задача коротко

Оператор підтримки «Сузірʼя» відповідає на звернення клієнтів. Факти — номер заявки, строки, куди привезти товар — він уже встановив (у ПР9 це робив workflow); лишилося написати відповідь людською мовою. Модель складає **чернетку**, оператор її редагує й надсилає.

Один виклик моделі ви робили ще в ПР3. Тепер цей виклик стоїть у застосунку, яким користуються весь день: провайдер відповідає по 10–20 секунд, іноді повертає 429 або 5xx, ключ може протермінуватися, а оператор, який не бачить, що відбувається, натискає кнопку ще раз. Тому в цій роботі модель — не головне. Головне — усе, що між HTTP-ендпоінтом і моделлю: **абстракція провайдера**, **таймаути**, **обмежені повторні спроби**, **контрольовані помилки**, **обмеження частоти**, **фонова генерація з потоком фрагментів**, **скасування** і **підставний провайдер**, з яким усе це можна перевірити без ключа.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Каркас застосунку |
| `samples/requests.json` | Вісім звернень із фактами, які встановив оператор, і прикладом відповіді — для підставного провайдера |
| `requirements.txt` | Залежності роботи |
| `.env.example` | Зразок налаштувань: провайдер і запасний варіант, доступ до моделі, таймаути, спроби, одночасність, ліміт на клієнта, поведінка підставного провайдера |
| `check_env.py` | Перевірка середовища: Python, пакети, `.env`, зразки, завершеність реалізації та пробний запит у режимі streaming |
| `eval/` | Перевірка стійкості й того, що бачить оператор, за переліком сценаріїв |

```
app/
├─ main.py                веб-рівень: сторінка, /api/drafts, потік подій, скасування
├─ providers/
│  ├─ base.py             контракт провайдера: Request, Chunk, Result, ProviderError
│  ├─ openai_compat.py    OpenAI-сумісний провайдер і переклад помилок SDK
│  └─ mock.py             підставний провайдер із керованими затримками й збоями
├─ gateway.py             таймаути, спроби, одночасність, запасний варіант
├─ jobs.py                фонова генерація, події та скасування
├─ limits.py              обмеження частоти для клієнтів власного API
├─ drafting.py            запит до моделі для чернетки й перевірка чернетки
├─ samples.py             читання зразків звернень
└─ templates/index.html   сторінка: звернення, чернетка, скасування, повтор, перелік
```

Застосунок зберігає чернетки й події в памʼяті процесу. Сторінка показує звернення з фактами, замовляє чернетку, слухає потік подій і показує стан: у черзі, генерується, спроба, провайдер, запасний варіант, час до першого фрагмента. Текст приходить фрагментами в поле, яке можна редагувати; є кнопки «Скасувати», «Повторити», «Скопіювати», перелік останніх чернеток (відкриття чернетки зі списку відтворює її події) і кнопка «надіслати 5 поспіль» для перевірки обмеження частоти. Чернетки доступні після оновлення сторінки, але не після перезапуску процесу.

## Початок роботи

1. **Середовище:**

   ```bash
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   copy .env.example .env
   ```

   Для macOS і Linux активація середовища — `source .venv/bin/activate`, копіювання — `cp .env.example .env`. Ключ доступу перенесіть у `.env` з папки попередньої роботи.

2. **Перевірка:**

   ```bash
   python check_env.py
   ```

   Запустіть заздалегідь. Скрипт зробить пробний запит у режимі streaming і покаже, через скільки прийшов перший фрагмент і скільки тривала відповідь, — від цих чисел відштовхуйтеся, обираючи таймаути. Якщо запит провалився, скрипт назве вид збою — той самий, який має розрізняти ваш провайдер.

Запуск застосунку з папки `pr10`:

```bash
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000. Для роботи без ключа задайте `LLM_PROVIDER=mock`; стан і текст чернеток зберігаються в памʼяті до перезапуску процесу. Прапорець `--reload` також перезапускає процес при зміні файлів.

## Що очікує сторінка

Замовлення чернетки — `POST /api/drafts` з `{"request_id": "d01", "client": "…"}`; у відповідь — статус 202 і знімок чернетки (`Draft` з `app/jobs.py` через `draft_to_dict`): `draft_id`, `status`, `text`, `attempts`, `provider`, `model`, `fallback`, `error`, `usage`, `elapsed`, `warnings`. Контрольована помилка API має формат `{"type": "…", "message": "…", "retryable": false, "request_id": "…"}`; для 429 додається заголовок `Retry-After`.

Далі сторінка відкриває `GET /api/drafts/{id}/events` і розуміє події `status`, `delta`, `done`, `error`, `cancelled` (їхні поля описано в `app/jobs.py`); інші показує в журналі як є. Статуси чернетки: `queued`, `running`, `done`, `failed`, `cancelled`. Скасування — `POST /api/drafts/{id}/cancel`; перелік — `GET /api/drafts`; знімок — `GET /api/drafts/{id}`; налаштування для шапки — `GET /api/health`.

## Реалізовані компоненти

| Де | Що зробити |
|---|---|
| `app/providers/openai_compat.py` | OpenAI-сумісний виклик; переклад помилок SDK у `ProviderError`; закриття потоку |
| `app/providers/mock.py` | Відповіді з `reply_example`, затримки й відтворювані конфігурацією збої |
| `app/gateway.py` | Три таймаути, обмежені повтори з backoff/jitter, semaphore, fallback і стан спроб |
| `app/jobs.py` | Фонове виконання, SSE-події, журнал стану в памʼяті та скасування |
| `app/limits.py` | Ковзне вікно ліміту на клієнта з `Retry-After` |
| `app/drafting.py` | Запит за підтвердженими фактами та попередження до чернетки |
| `app/main.py` | HTTP API, 202/429/404/409 і спільний формат контрольованих помилок |

## Чекліст самоперевірки

- [ ] Чернетка генерується у фоні: `POST /api/drafts` повертається одразу, текст приходить фрагментами, сторінка показує стан на кожному етапі.
- [ ] Провайдер за контрактом `providers/base.py`; решта застосунку не імпортує `openai`; перемикання `LLM_PROVIDER=mock` не потребує змін у коді.
- [ ] Три таймаути діють і перевірені: на спробу, на бездіяльність у streaming, на весь запит; значення обґрунтовано вимірюванням.
- [ ] Повторюються лише тимчасові збої, з наростаючою паузою й випадковою часткою, не більше `LLM_MAX_ATTEMPTS` і не довше за `LLM_TOTAL_TIMEOUT`; `Retry-After` провайдера враховано.
- [ ] Збій провайдера після всіх спроб стає подією `error` з видом, повідомленням для людини й ознакою «можна повторити», а не винятком і не 500.
- [ ] Одночасні звертання до провайдера обмежено на весь застосунок; частоту замовлень обмежено на клієнта, відмова — 429 з `Retry-After` і тілом у єдиному форматі.
- [ ] Запасний варіант вмикається за налаштуванням і позначений у результаті; оператор бачить, що чернетка не від основної моделі.
- [ ] Скасування зупиняє роботу між фрагментами й спробами; скасована чернетка не стає `done`; скасування завершеної чернетки — зрозуміла відмова.
- [ ] Перезавантаження сторінки посеред генерації не втрачає чернетку: її видно в переліку, відкриття відтворює події.
- [ ] Жодна чернетка не лишається в `running` після збою; журнал подій пояснює, що сталося.
- [ ] Чернетка — текст, який редагує людина: правки не губляться при повторі без підтвердження; підставний провайдер і запасний варіант позначені.
- [ ] Підставний провайдер відтворює затримки й усі види збоїв із `.env`; сценарії з `eval/` прогнано, висновки записано.
- [ ] Ключ не потрапив ані в код, ані в репозиторій, ані у відповіді й повідомлення про помилки.
- [ ] Ви можете пояснити кожне ухвалене рішення.
